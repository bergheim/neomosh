#+title: Neomosh — project context

* Purpose and audience
Neomosh is a modern Mosh fork for developers and terminal users. Its identity should emphasize persistent connections, roaming, and responsiveness. The inherited Mosh implementation provides remote terminal sessions, predictive local echo, and recovery from intermittent connectivity.

* Constraints and decisions
The project name is Neomosh, styled as =neomosh= in logo concepts. There is no fixed palette; explore freely. The first identity study compares three SVG logo concepts each from Codex, Claude, and Grok on one HTML page. No final logo has been selected.

* Context source
The purpose, audience, and identity brief above were confirmed by the user on 2026-09-07. =README.md= still describes upstream Mosh; recent source history includes OSC 8 hyperlink support.

* Upstream relationship
Upstream mobile-shell/mosh last released 1.4.0 in October 2022. Its master as of 2026-09-08 is 39 commits ahead of that, and this checkout sits at that head; the only user-visible addition is OSC 8 hyperlinks. Review upstream is slow, so open upstream PRs and the jdrouhard/mosh patched branch (undercurl, Unicode overhaul, out-of-band channel with agent forwarding) are treated as a cherry-pick source. The surveyed items live in =docs/TODO.org= under the =upstream= and =jdrouhard= tags.

* Wire compatibility decision
Decided 2026-09-08: neomosh does not maintain wire compatibility with upstream mosh. Both ends must be neomosh. The launcher verifies this with a version handshake and refuses a stock mosh-server, with an explicit escape hatch that disables neomosh-only features. This frees the framebuffer diff (renditions, Unicode occupancy), the user-input stream (theme events) and the transport (out-of-band channel) to change without dual-format code.

* Image protocol decision
Decided 2026-09-08: Kitty graphics protocol only, no sixel. Ghostty, kitty, WezTerm and Konsole speak Kitty; Ghostty dropped sixel in November 2024. Kitty's image ids and placements map onto a cell-based framebuffer, sixel's raw pixel bands do not.
Decided 2026-09-08 after review (Codex, Grok, Claude subagent): image bytes ride the state sync instruction stream as a new HostMessage extension in ack-paced batches; the out-of-band channel is not a prerequisite for graphics. Pixel window size propagation (ws_xpixel, ws_ypixel, XTWINOPS 14 and 16) lands first because kitten icat refuses to run without it.
Decided 2026-09-08 during implementation: placements are metadata on the anchor row, not per cell and not a separate table; the server stores opaque bytes and never decodes; internal id and placement uid counters never reset within a session; the client remaps ids into a random high range and refuses pixel transmits over APC; nothing advertises graphics until the host test passes.

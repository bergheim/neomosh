#+date:       [2026-09-08 Tue 15:33]

* Goal
Show images placed with the Kitty graphics protocol by a remote app through neomosh in a local terminal that speaks it (Ghostty, kitty, WezTerm, Konsole), with the same semantics as over ssh: the image sits at its cell position, scrolls with the text, and survives a link drop and roam. Acceptance for v1: =kitten icat foo.png= over neomosh into Ghostty, then scroll it off, then drop the link and reconnect. Decision in PROJECT.org: Kitty only, no sixel.

* Why the existing diff cannot carry pixels, and why OOB is not needed either
Server to client state is =Terminal::Complete=. =Complete::diff_from= produces a =HostBuffers::HostMessage= whose =hostbytes= instruction is the escape string from =Display::new_frame=, and the client feeds that string into its own emulator. Placements fit that model (they are a few bytes of APC per image); image bytes do not: the diff is regenerated from the assumed receiver state on every send, the sender keeps up to 32 copies of the state, and every send gets a fresh fragment id, so one lost fragment loses the whole instruction until the retransmit. A single instruction holding a multi-megabyte image would rarely complete on a lossy link. The earlier plan made the jdrouhard out-of-band channel a prerequisite. Three independent reviews (Codex gpt-6-astra, Grok 4.6, a Claude subagent with repo access) and a check of the transport agreed that it is not: image bytes can ride the same =HostMessage= as a new protobuf extension and use mosh's own ack and resend, as long as each instruction stays small. The sender's optimistic assumption (states sent within the timeout window are assumed received) means a batch goes out once and is only resent after the timeout. Head-of-line isolation is the only thing OOB adds; it stays deferred to the agent-forwarding task.

* Prerequisite: pixel geometry
=kitten icat= exits with "Terminal does not support reporting screen sizes in pixels" when TIOCGWINSZ reports zero =ws_xpixel= and =ws_ypixel=. Today only rows and columns cross the wire (=userinput.proto= ResizeMessage) and =mosh-server.cc= sets only =ws_col= and =ws_row= before TIOCSWINSZ, so every remote pty under mosh reports zero pixels. The emulator also has no handler for CSI 14 t and CSI 16 t. This lands first as its own branch: the client forwards =ws_xpixel= and =ws_ypixel= in the resize event, the server applies them with TIOCSWINSZ and keeps them in the draw state, and the emulator answers XTWINOPS 14 (window size in pixels) and 16 (cell size in pixels), silent when unknown. Pixel size is excluded from =DrawState::operator==(= so a pixel-only SIGWINCH does not create an empty state. Bounds are validated like the existing width and height. This is useful on its own for timg, chafa, yazi and image.nvim, none of which work over mosh today for the same reason. Upstream has no issue or PR for it.

* Server emulator
Parser: the vt500 state machine swallows APC payloads in =SOS_PM_APC_String=. Add an =APC_String= state mirroring =OSC_String= with APC start, put and end actions, routed from ESC _ and 0x9F; SOS and PM keep the swallowing state. The dispatcher buffers the APC payload with an 8 KiB cap (a Kitty chunk is at most 4096 base64 bytes plus keys) and hands payloads starting with =G= to a Kitty module in =src/terminal/kittygraphics.*=. The server never decodes images. It stores opaque bytes plus format and dimensions (from =s= and =v= for raw formats, from the PNG IHDR for f=100). The store is keyed by an immutable internal id; the app-visible id (or an implicit id when =i= is absent) maps to the current internal id, and re-transmitting an id creates a new internal id so retransmitted diffs stay idempotent. The =m=1= chunk accumulator lives in the dispatcher, outside state equality, like the OSC buffer; an image enters the state only when complete. Caps: 8 MiB per image, 32 MiB total, evict the oldest unplaced image first. Commands in v1: =a=q= answered OK for direct transmission (t=d) and with an error for file, temp file and shared memory, so =kitten icat= falls back to direct; =a=T= stores and places at the cursor with extent from =c= and =r= or from pixels over the cell size, 1x1 when the geometry is unknown; =a=d= for all, all-and-free, by id, and by id-and-free; =q= gates replies, which echo the app id. =a=p= from the app is not needed for icat and comes later. Replies go through the existing terminal-to-host path from =Complete::act=. Placements are metadata on the top =Row= of the image, shared-rep like =Hyperlink= on cells: internal image id, placement id, columns, rows, z-index. Rows are =shared_ptr= with copy-on-write and =Display::new_frame= detects moved row pointers, so scrolling, insert and delete line, equality and diffing come for free. A placement is dropped when its row leaves the screen and when =Row::reset= clears it (CSI ED). The emulator has no alternate screen (mode 1049 is not in its mode table), so there is nothing to swap. Kitty does not delete an image when text overwrites cells under it, which is why the placement is not per-cell metadata.

* Wire format
=hostinput.proto= gains an =ImageChunk= extension: internal id, offset, data, total length, format, width, height. =Complete= holds the store with blobs by =shared_ptr= and an admitted-bytes counter per image. =diff_from(existing)= emits, for each image that =existing= lacks or has fewer admitted bytes for, one chunk covering exactly that gap. That is a pure function of the two states, which =Fragmenter::make_fragments= requires: it asserts identical diffs for identical state numbers. =apply_string= creates or appends on the client. Pacing lives in the server main loop, not in the state: after host reads, when unadmitted bytes exist and the acked state number has passed the last admit marker, admit one 32 KiB batch (about 25 fragments at the 1280 byte MTU), record the last sent state number as the marker, and push the state. Stop-and-wait gives one batch per round trip; a lost batch costs one batch, not the image. The select timeout is clamped to 50 ms while bytes remain. =Display= gets a graphics mode: NONE, WIRE (used by =Complete= on the server), KITTY (used by the client when the probe succeeds). In WIRE mode =put_row= diffs old and new row placements after the identical-pointer shortcut and emits positioned =a=p= and =a=d= with =q=2= and internal ids. The client emulator resolves =i= as internal ids and never replies; =apply_string= asserts that. Scrolled placements need no re-emission because the scroll shortcut moves row pointers on both ends.

* Client rendering
At connect (and resume) the client sends a Kitty query probe after the theme probe: =a=q,t=d,f=24,s=1,v=1,i=31= with three payload bytes. =TerminalReplyFilter= learns the =ESC _ G ... ESC \\= reply shape with a 500 ms deadline while the probe is outstanding and a larger held-bytes cap. An OK reply switches the Display to KITTY mode and requests a repaint; no reply or an error leaves graphics off silently, which covers local tmux and unsupported terminals. In KITTY mode the Display remaps internal ids to local ids so it never collides with images another process left in the terminal. When a placement's blob is complete and not yet uploaded it sends =a=t,m=1,q=2= chunks of at most 4096 base64 bytes, then =a=p=. Placements whose blob is incomplete are skipped and their rows are forced past the pointer shortcut once the blob completes. Images gone from the store get =a=d,d=I=. Mosh repaints with ESC [ H ESC [ 2 J, which does not remove Kitty images, so every full repaint first emits =a=d,d=a=. =shutdown()= writes =a=d,d=A= before closing the display.

* Out of scope for v1
Known v1 limitations, accepted after the second review round: a placement lives on its top row only, so an image whose top row scrolls off the screen disappears even if lower rows would still be visible (kitty keeps drawing the visible part; fixing this needs per-row coverage metadata). An APC string dispatches when the parser leaves the string state on any ESC, not only on ESC backslash, which mirrors how this parser already treats OSC strings; a malformed app that abandons an APC and continues with another escape sequence gets its command executed anyway.
Out-of-band channel. Unicode placeholders (U=1), which also means =kitten icat= inside a remote tmux shows nothing. Animation frames. Cursor movement variants beyond the default. Capability advertising: nothing announces graphics in DA1, XTGETTCAP or anywhere else until the acceptance test passes. File and shared-memory transmission stay rejected forever, they assume a shared filesystem.

* Verification
Unit tests through =Complete::act= and a =diff_from= then =apply_string= round trip: APC parsing, chunk assembly, replies and =q= gating, store caps, scroll-off, ED, partial-admission diffs being deterministic. The e2e harness runs under tmux, which swallows APC, so nothing image-related can be checked with capture-pane; the host check is =kitten icat= into Ghostty, =yes | head -50= to scroll it off, toggling the link, and =reset=.

Deviations from this note that landed during review: placements carry a wire-unique uid and the anchor column; image numbers (I=) are supported; counters for internal ids and uids never reset; the client refuses APC pixel transmits; placement removals and additions are emitted per frame, removals first; local ids on the client come from a random base in the high half of the id space; shutdown deletes every uploaded image with d=I.

* Field finding 2026-09-09: unchunked APCs
The first host test showed tiny icons rendering and every larger image as a blank line. Tracing with a temporary NEOMOSH_KITTY_LOG (branch debug/kitty-logging) showed the whole pipeline correct and the image simply never reaching the Kitty module: kitten icat transmits a whole image as one unchunked APC (a 2.4 KB icon arrived as a single 3175-byte payload), and the dispatcher discarded any APC over 8192 bytes silently. The APC cap is now derived from the per-image cap (base64 expansion plus headroom); the per-image cap is 16 MiB and the store 64 MiB so a full-window PNG fits. Two things that looked like bugs were not: icat centres images by default, so a placement at column 71 of 147 is correct, and mosh re-diffs against the assumed receiver state several times before an ack, so the same image chunk legitimately appears in several diffs. Snapshot copies of the in-flight APC buffer are an accepted transient cost, tracked in the follow-ups task.

* Review record
Reviewed 2026-09-08 by Codex (gpt-6-astra), Grok 4.6 and a Claude subagent against the first assessment. Findings adopted: OOB is not a prerequisite; the server stores opaque bytes; pixel geometry is a hard missing prerequisite; the client emulator must not reply; diffs must be deterministic; blobs must be shared between sent states; a full repaint does not clear images; ids must be remapped on the client; row-attached placements beat a placement table; "detach and reconnect" is not a mosh operation, the test is a link drop and roam. Upstream mobile-shell/mosh has no graphics PR; issues 1081, 1166, 1248, 1093 and 1274 were closed as too large for the state sync protocol. The jdrouhard fork has no graphics commits. Nothing to cherry-pick.
Per-branch review findings that changed the code, all caught by Codex on the diff before landing. Pixel size: a two-argument resize wiped the stored pixels (Grok, fixed by making omitted arguments keep the current value). Emulator: unbounded image and placement counts, integer overflow on huge c and r, signed-shift undefined behaviour in the base64 decoder, missing anchor column, C=1 scrolling, discarded image numbers, replacement rejected at capacity, d=I freeing data with placements left, number-map leak on d=A, atoi on untrusted input, auto-allocated ids colliding with app ids, rows clamped in the stored extent. Wire: placement emitted before its image entry existed, an assert reachable from the peer, deleted images never leaving the client store, internal ids reused after RIS, the scroll fallback deleting a placement it had just moved, later chunks trusted for total and metadata, empty chunks with quadratic cost, admitted and pending maps leaking on d=A; plus a pre-existing bug where placement edits did not bump Row::gen and confused the scroll shortcut. Client: resume kept stale uploads and ids, local ids from 1 collided with images already in the terminal, shutdown's d=A missed unplaced uploads, resume orphaned image data, and a placement removal allocated a local id. Grok headless could not review diffs of this size and Gemini has no auth in the container; the cross-agent notes in stash record the details.

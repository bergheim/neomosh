#+title:      Theme propagation: OSC 10 and 11 and mode 2031 over the user stream
#+date:       [2026-09-08 Tue 07:21]
#+filetags:   :design:terminal:theme:
#+identifier: 20260908T072137

Why: over ssh a remote app talks straight to the local terminal, so vim, neovim and friends can ask for the background colour (OSC 11 ;?) or the light/dark preference (CSI ? 996 n) and subscribe to changes (DEC private mode 2031, notified as CSI ? 997 ; 1|2 n). Mosh runs its own emulator on the server and never forwards queries, so those apps saw nothing and defaulted to dark. Neomosh replicates the answers on the server from values the client learns from the real terminal.

Client side (src/frontend/stmclient.cc, src/frontend/terminalreply.*): after Display::open the client writes CSI ? 2031 h, CSI ? 996 n, OSC 10 ;? and OSC 11 ;? to the local terminal, again after SIGCONT. Replies arrive on stdin mixed with keystrokes, so a small filter (TerminalReplyFilter) recognises exactly the three reply shapes and passes everything else through as keystrokes. It only holds back bytes that are a strict prefix of a reply, and a 100 ms deadline in the select loop flushes them as keystrokes, so a user typing ESC never stalls. A completed reply becomes a Parser::Theme event (foreground, background as XParseColor rrrr/gggg/bbbb, scheme 0 unknown, 1 dark, 2 light) pushed onto Network::UserStream, next to Resize. An unsolicited 997 report triggers a fresh OSC 10 and 11 query so the colours follow the scheme. Display::close sends CSI ? 2031 l.

Wire (src/protobufs/userinput.proto, src/statesync/user.*): ThemeMessage is an optional extension on Instruction. A stock mosh-server ignores it, a neomosh server with a stock client simply never learns a theme, so no handshake is needed for this feature.

Server side (src/terminal/terminaldispatcher.*, terminalfunctions.cc): the values live in the Dispatcher, not the Framebuffer, on purpose. Framebuffer state is what Complete::diff_from compares and Display::new_frame serialises, and the client already knows its own theme, so putting it there would only bump state numbers for nothing. The dispatcher answers OSC 10 ;? and 11 ;? and CSI ? 996 n only when it has a valid value, tracks mode 2031 from DECSM and DECRM (cleared by ESC c, kept across DECSTR), and Dispatcher::set_theme appends CSI ? 997 ; N n to terminal_to_host when 2031 is on and the scheme actually changed.

Terminal support checked 2026-09-08: mode 2031 with 996 and 997 is implemented by Ghostty, kitty and Contour, and tmux merged it for the release after 3.5. tmux 3.7 forwards both the OSC 11 query and CSI ? 996 n to its outer terminal. Confirmed on the host 2026-09-08: neovim over neomosh into berghome switches theme live, both directly in Ghostty and inside tmux. foot unconfirmed. Terminals without 2031 still get the OSC 10 and 11 snapshot at connect and after SIGCONT.

Verified 2026-09-08 with a real mosh-server and mosh-client in a Python pty harness that answered the probe: a remote printf of OSC 11 ;? and CSI ? 996 n read back rgb:1010/2020/3030 and CSI ? 997 ; 1 n; after the remote enabled mode 2031, injecting CSI ? 997 ; 2 n on the client tty produced CSI ? 997 ; 2 n on the remote pty; a later OSC 11 query still answered; the client sent CSI ? 2031 l on exit. Harness gotchas: the remote pty must be in raw mode (stty raw -echo min 0 time 20, then cat -v) because canonical mode holds a reply with no newline, and busybox timeout puts cat in a background process group that is stopped on tty read. The pty needs a non-zero window size or mosh-client asserts in Framebuffer.

Not done: OSC 4 palette queries, an automake e2e test (the tmux framework was not tried; the Python harness above is the recipe), and a periodic re-query for terminals without 2031.

User verification 2026-09-08 from tux (Ghostty) to berghome, running ssh -> tmux -> nvim --clean and toggling dark mode with toggle-darkmode: plain ssh switches, stock mosh 1.4.0 stays dark, neomosh switches. So tmux 3.7 does pass the 2031 notification and OSC 11 reply back into the pane. Note the nvim config caveat: any script that sets background (including colorschemes such as carbonfox) turns off Neovim own detection; derive the theme from the TermResponse OSC 11 reply instead.
